ReceivePayment — Customer Pays Their Invoice (AR Clearance) CRITICAL GAP
UI: receive_payment.html / s6_receive_payment.js → nativeApi.call('receivePayment', {customerId, amount}) → MainActivity.kt → CustomerRepository.receiveCustomerPayment()
SeqConditionDebit (Dr)Credit (Cr)Status
1 subType = NULL (cash assumed) 1000 Cash 1002 Accounts Receivable NEVER POSTS
What happens today (broken) receiveCustomerPayment() correctly inserts a paymentReceived row and creates paymentApplied rows against open invoices. It marks invoices as "Paid" in the invoice table. But it never calls insertAccountingTransactionAndPostJournal().

Result: account 1002 (Accounts Receivable) in journalEntries is never credited. Cash received is never debited to account 1000. The balance sheet shows AR growing forever and cash never increasing from customer payments.
Missing: Cash vs Bank routing The current journal rule has subType = NULL, meaning it always debits 1000 Cash. If the customer pays by bank transfer, the debit should go to 1003 Bank instead. A paymentMethod parameter needs to flow from the UI through to a ReceivePayment/Bank journal rule (Dr 1003, Cr 1002).
Where to add the fix In CustomerRepository.receiveCustomerPayment(), after inserting the paymentReceived row, add:
helper.insertAccountingTransactionAndPostJournal( AccountingTransactionInput(type="ReceivePayment", subType=null, table="paymentReceived", refId=newPaymentId, amount=amount) )
Invoice — Monthly Customer Invoice Document DOC ONLY
Auto-created inside recordSale() — not a separate user action
No journal entries. The Invoice TransactionType exists in the DB but has moduleId = NULL and no accountingJournalsMap entry.

The invoice is purely a document — it groups all daily sales for a customer into a monthly billing statement. Revenue was already recognised by the Sale TxnType when each daily sale was recorded. Invoice status (Draft → Open → Paid) is updated automatically as payments are applied.

Gap Summary — What Needs to Be Fixed

Priority Gap Symptom on Books Fix Location
CRITICAL ReceivePayment journal never posts. receiveCustomerPayment() does payment tracking but never calls insertAccountingTransactionAndPostJournal(). AR (1002) never decreases. Cash (1000) never increases from customer payments. Balance sheet AR grows forever. Add insertAccountingTransactionAndPostJournal() call inside CustomerRepository.receiveCustomerPayment() after the paymentReceived insert.
HIGH ReceivePayment has no Cash vs Bank subType routing. Current rule always debits 1000 Cash. Bank transfers from customers will incorrectly increase Cash instead of Bank. Add a paymentMethod param to the receive payment UI and backend. Add ReceivePayment/Bank rule (Dr 1003, Cr 1002) to accountingJournalsMap.
MEDIUM BatchSoldCogs never fires. COGS (5001) and Inventory (1010) are never adjusted at point of sale. Milk inventory (1010) stays high permanently. COGS is always zero. Gross profit is massively overstated. Build batch settlement logic. Call insertAccountingTransactionAndPostJournal(type="BatchSoldCogs") when a batch is settled/closed.
MEDIUM PayableSettlement has no Bank option — all operational payable settlements assume Cash only. Bank transfers for wages/rent will incorrectly reduce Cash (1000) instead of Bank (1003). Add PayableSettlement/{Wages|Rent|Electricity|Fuel}/Bank rules (Dr payable, Cr 1003) and a payment method selector in the settlement screen.
LOW No Expense/Vet daily accrual. Vet costs only flow through WIP capitalisation. Vet costs are capitalised to WIP but never first accrued to a payable. Only matters if vet bills are owed before payment. Add Expense/Vet → Dr 7001, Cr (new) Vet Payable rule if accrual accounting for vet bills is needed.
LOW AccountingLogic.md incorrectly lists both 7000 and 7001 as "Vet Expense" (stale doc). No effect on actual data — DB seed is correct (7000 = Electricity, 7001 = Vet). Update AccountingLogic.md COA table. The code is already correct.
